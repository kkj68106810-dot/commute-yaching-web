기본 화면에 대한 생각

1. B2C 사용자 프론트엔드 (통근 시뮬레이터 웹)
일반 사용자가 직주근접과 야칭 예산을 고려해 최적의 거주지를 탐색하는 핵심 서비스 화면입니다.

사용 기술: Next.js (App Router, TypeScript), Tailwind CSS, React Leaflet (또는 Mapbox).

주요 화면 및 기능:

다중 조건 검색 필터 화면: 근무지 역, 지불 가능한 최대 야칭(월세), 방 구조(1K, 1LDK 등), 최대 환승 횟수를 설정하는 UI를 제공합니다. URL Query Parameters를 적극 활용하여 사용자가 새로고침을 하거나 링크를 공유해도 검색 필터 상태가 완벽히 유지되도록 구현합니다.

지도 시각화(Map) 화면: 검색 조건을 만족하는 추천 지하철역의 위도/경도 좌표를 바탕으로 지도 위에 마커를 렌더링합니다. 마커 클릭 시 해당 역의 평균 야칭, 예상 통근 시간 등의 상세 정보가 팝업으로 표출됩니다.

다국어 지원(i18n) UI: 일본 현지 채용을 타겟팅하여 한국어와 일본어 실시간 토글 기능을 화면 상단에 배치합니다. SEO(검색 엔진 최적화)와 빠른 초기 로딩을 위해 SSR(Server-Side Rendering)을 적용합니다.

2. B2B 관리자 프론트엔드 (백오피스 CMS)
대량의 지하철역 데이터와 부동산 통계 데이터를 효율적으로 제어하기 위한 사내 관리자용 대시보드 화면입니다.

사용 기술: Next.js (CSR 중심), MUI (Material-UI) 또는 Ant Design 템플릿.

주요 화면 및 기능:

관리자 로그인 화면: JWT(JSON Web Token) 기반의 인증 절차를 거쳐 인가된 관리자만 대시보드에 접근할 수 있도록 보안을 처리합니다.

데이터 관리(CRUD) 대시보드 화면: 일본 전국의 전철역 노선 데이터 및 역별 평균 야칭 통계(Batch) 데이터를 조회, 등록, 수정, 삭제합니다.

데이터 그리드 화면: 대용량 데이터를 한눈에 파악할 수 있도록 데이터 테이블(DataTable) 컴포넌트를 활용하며, 정렬(Sorting), 페이징, 필터링 기능을 통해 백엔드(Spring Boot API)와 통신합니다. 서버 부하를 줄이고 부드러운 화면 전환을 위해 CSR(Client-Side Rendering) 위주로 구성합니다.
